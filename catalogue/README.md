# Catálogo público de la extensión

`latest.json` apunta a `releases/<revision>.json` mediante SHA-256 de **los bytes exactos** del archivo. La extensión descarga ambos desde la ruta fija `raw.githubusercontent.com/samuelcorsan/reforma-digital/main/catalogue/`, sin parámetros, cuerpo, credenciales, cabeceras de perfil ni contexto de la persona. Solo guarda la última versión íntegra en `chrome.storage.session`, que no persiste en disco. El catálogo inicial está vacío: ninguna guía ni flujo se declara disponible antes de superar sus comprobaciones.

Para publicar una revisión futura, crea `releases/N.json` con `revision` mayor, calcula `sha256sum catalogue/releases/N.json` **después de formatear**, actualiza `latest.json` con esa huella y revisa ambos archivos en el mismo cambio. Incluye solo `Guide` con validación automática `verified` y fuentes aprobadas. Conserva todas las bajas de `retiredGuides`; toda guía que desaparece necesita una baja explícita. Conserva cada ID de flujo con estado `retired` cuando se retire. El campo de flujo solo anuncia ID, versión empaquetada y estado; nunca contiene `FlowMap`, selectores, transiciones, JavaScript ni una nueva capacidad de automatización. El lector solo marca un flujo como disponible si su ID y versión figuran en el registro empaquetado que le pasa el cliente; esta extensión aún no le pasa ninguno.

El worker expone `catalog:refresh` para descargar y validar, y `catalog:read` para consultar la copia de esta sesión. Una descarga correcta marca la copia como comprobada durante el día de consulta. Si falla una actualización, se borra esa marca: la copia anterior se muestra fechada como no vigente y ningún flujo disponible se declara habilitado, también en lecturas posteriores. Una baja ya conocida sigue marcada como retirada. Al cambiar de día o caducar la revisión, ocurre lo mismo hasta completar otra descarga. Una versión anterior, corrupta, inconsistente o con campos no admitidos no sustituye a la última válida. Reiniciar el navegador elimina la copia de sesión.

Hasta que el cambio comprobado de `dev` llegue a `main`, la URL pública aún no contendrá estos archivos; el lector devolverá un catálogo vacío. La fuente HTTPS y la huella detectan corrupción o desajuste entre puntero y release, pero no sustituyen el control de publicación del repositorio ni verifican por sí solas las fuentes jurídicas. La incorporación de guías y de mapas empaquetados se valida en sus tickets específicos.
